SoundScope optional Meta features

Implementation checked against official documentation on 2026-11-04.
No paid API request was used to develop or test this adapter. Passing offline
tests establishes budgets, parsing and integration behavior, not model accuracy
or access for a particular account.

Models and responsibilities
* muse-voice-transcribe-1.0: an explicit short spoken command -> text.
* muse-spark-1.3: command interpretation and optional visual scene context.
  Experimental sound descriptions use a spectrogram image, not direct audio.
  They are always marked unverified, including when the model sounds confident.
* sam-3.1: manual point-prompt segmentation on an event snapshot. The point must
  come from the acoustic candidate. Segmentation does not verify that an object
  emitted the sound. Returned outlines only belong to that captured snapshot.

Credit controls
Disabled by default, including when MODEL_API_KEY is present. Default maximum
five attempted requests per adapter instance, plus a persistent maximum twenty
per UTC day across instances using the same state directory. Failed and invalid
responses count. Each operation makes at most one HTTP attempt; redirects and
automatic retries are disabled. Identical successful requests use a persistent
cache and cost no new request. Text output is capped at 1200 tokens per call.
Request counts are not a guaranteed dollar budget. SAM output is bounded by
response size and time, rather than the text-completion token parameter.

The SQLite cache contains hashes and model results; it does not contain source
audio, images, credentials or prompts. Transcripts and resulting descriptions
can still be personal data. No contributor models are selected. State directory
must remain private and shared across this application's optional Meta entry
points for its daily cap to be effective.

Limitations
No streaming diarization implementation. Official docs do describe diarization,
but assigning speaker turns to live acoustic locations needs synchronization
and evaluation; it is not just a guessed flag on the existing transcription call.
Audio support in Spark 1.3 is documented as degraded/not fully supported. A
spectrogram is not a reliable replacement for an evaluated audio classifier.
Visual context describes objects near a pixel in the image, not metric distance
and not proof that those objects made the sound. No model is allowed to calculate
robot calibration, override acoustic localization or directly move the arm.

Input/output contract
SemanticMeta(store,state_dir,enabled=False,max_calls=5)
Store implements get(event_id) and update(event_id,patch).
Event pixel=[u,v] refers to its original snapshot, not a resized browser view.
Audio input: WAV bytes, 16 kHz mono signed 16-bit, at most 10 seconds.
Images: JPEG bytes, <=1.5 MB and <=2.1 million pixels.
segment_at(jpeg,event_id,[u,v]) returns segmentation.width/height, point_xy,
snapshot_only=True and objects with box_xyxy and polygons in original pixels.
Box right and bottom coordinates are exclusive. Polygons approximate exterior
mask contours; holes are not drawn. Masks not containing the acoustic point are
discarded. source_verified=False remains explicit.

Install optional SAM decoder with:
  python -m pip install -r requirements-semantic.txt
Offline checks:
  python -m unittest test_semantic_meta -v
